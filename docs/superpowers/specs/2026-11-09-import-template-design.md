# Import workbook template and guide — design (small change)

## Intent

The import is for people who start a new tracker in Excel. Today the import page only says "the standard tracking
layout", so a new user has nothing to start from and learns the layout from error messages. They get a template that
teaches the layout by example, and a short guide on the page.

## What gets built

1. **Import page:** a "Download the template" link and a "What the workbook needs" section that opens on request:
   the five sheets in one line each, and the totals rule (completed so far on By Location = completed before the
   first report + the weekly actuals).
2. **The template workbook** (`import-template.xlsx`):
   - An **Instructions** sheet first: what each sheet is for, which cells to fill, the rules (real Excel dates,
     values from the lists, at most 52 weeks, 6 locations and 15 risks), and how to import.
   - The five sheets the importer reads, with every input cell labelled, input cells shaded, drop-down lists for
     RAG, risk Status and Report day, and date formats set.
   - Filled in with the Network refresh example used for the email mock-up: three locations, eight weeks of
     targets and actuals, three risks and a weekly update, reconciling so that it imports as it stands.
3. **Example warning on the preview page:** when the workbook still holds example values (location names, risk
   descriptions, the update text), the preview names each one and asks to replace or delete them. The import is not
   blocked.

## How it is built (approach C, chosen)

The template is a file stored in the repository and served as it is. A command, `flask build-import-template`,
regenerates it from the same cell positions the importer reads. A test regenerates the workbook in memory and compares
every cell value, list and sheet of the stored file with it, so a stored file left behind by a layout change fails
the tests. A second test imports the stored template and checks it reconciles.

Approaches considered: A (generate on each download; always in step, no stored file), B (a hand-made stored file;
drifts silently), C (stored and regenerated by a command; chosen by the owner, with the comparison test removing
the drift risk).

## Calls made by the builder

- The example values to warn about are those of the shipped example only; a workbook whose real location is
  "London" still imports after the warning.
- The download needs sign-in and the same permission as the import page.

## Non-goals

- No change to which cells the importer reads or how it validates them.
- No template for adding history to an existing tracker.
