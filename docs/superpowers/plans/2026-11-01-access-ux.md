# Access screens usability redesign Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the Teams, team, Users, Effective access and tracker Access screens show where access comes from, preview team moves, and fit the screen.

**Architecture:** Two new pure-ish helpers (`tracker/teams/people.py` for who reaches a team, `tracker/teams/impact.py` for a move's effect) feed reworked Jinja templates. One new static script, `tracker/static/admin.js`, adds three progressive enhancements (tree filter, row filter buttons, select filter); every screen works without it. No POST endpoint changes its fields, guards or activity entries.

**Tech Stack:** Flask, SQLAlchemy 2, Jinja, Postgres, pytest (+ Playwright browser tests marked `browser`).

**Spec:** `docs/superpowers/specs/2026-11-01-access-ux-design.md`

## Global Constraints

- Strict CSP: no inline `<script>`, `<style>`, `style="…"` or `on*` attributes. Scripts load as `<script src="{{ url_for('static', filename='admin.js', v=app_version) }}" defer></script>` inside `{% block head_extra %}`.
- Every POST form carries `{{ csrf_field(csrf_token()) }}`.
- Copy is British English, formal, active voice, no contractions.
- Every screen works without JavaScript: controls that only work with it (filter boxes, filter buttons) render with `hidden` and `admin.js` reveals them; role selects use the existing `data-autosubmit` + `data-autosubmit-fallback` pattern in `tracker/static/tracker.js`.
- No page-level horizontal scroll at 390 px or 1,440 px; wide tables scroll inside their `.section-table` box.
- Inactive (pending or disabled) users never count as reaching a team or tracker.
- Permissions and POST behaviour are unchanged: `manage_teams` guards the Teams screens and tracker Access, `manage_users` the Users screens.
- Tests run only through `scratchpad/tools/acc-test.sh` against `tracker_test_design`, one run at a time (`pgrep -af pytest` first).

## Review Focus

1. A person who reaches a team or tracker by several routes (member of Infrastructure as owner and of Windows as viewer) appears once, with the highest role and every route. Tests: Task 1, Task 6.
2. The move preview changes nothing: the parent stays, no activity entry is written, and the following POST still runs every guard. Tests: Task 2.
3. Hand-made query strings (`?parent_id=abc`, `?team=99999999999999999999`, `?status=bogus`) give a 400 or are ignored, never a 500. Tests: Task 2, Task 4.
4. Without JavaScript the whole tree shows, filters stay hidden, the Set role button works and the More menu opens (it is a `<details>`). Tests: Task 3, Task 4, Task 6 (HTML assertions).
5. Team and person names with markup or quotes, which now also sit in `data-search` attributes, render escaped. Test: Task 3.
