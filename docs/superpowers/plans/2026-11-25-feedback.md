# Feedback Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let everyone signed in send ideas and problems (with files and screenshots) from a link on every page, keep
each as a request in the app, and let people with Manage feedback review, reply and set its status while the sender
follows it on My feedback.

**Architecture:** A new `tracker/feedback/` blueprint holds the routes, a service module the rules, a mail module the
three emails and a settings module the two `app_settings` keys. Three tables (requests, messages, files; files as
`bytea`, as `report_sends.pdf`) come in migration 0015. The pages reuse the standard table toolkit
(`lists/_table.html`, `lists.js`), the permission sets side panel pattern (`permsets.js`, a `/panel` route) and the
`list-dialog` pop-up.

**Tech Stack:** Flask 3.1, Jinja (StrictUndefined), SQLAlchemy, Alembic, PostgreSQL, vanilla ES5, CSS; pytest +
Playwright.

**Spec:** `docs/superpowers/specs/2026-11-25-feedback-design.md` (read Goals and "Calls made"; the canvas
https://claude.ai/artifact/GsqbHSLGYp93GzEeiLksFf shows every screen).

## Global Constraints

- Strict Content Security Policy: no inline script or style, no `style=` attributes; ES5 in `tracker/static`. Emails
  are the exception: `mail/feedback/*.html` use inline styles as `mail/access/*.html` do, and are added to `EXEMPT` in
  `tests/test_templates.py`.
- British English, no contractions; the spec's copy is the copy.
- Never an email address in the code: the recipients come only from the `feedback_email` setting; the sender is the
  signed-in user.
- Files: at most 5 per message, 5 MB each; PNG, JPEG, GIF, WebP, PDF, DOCX, XLSX, TXT, CSV, checked by content as well
  as by name; never SVG or HTML. Served only to the request's sender and to Manage feedback holders, with `nosniff`;
  pictures inline, the rest `Content-Disposition: attachment`.
- Only the feedback POST routes raise the 1 MB body limit (`request.max_content_length = 26 * 1024 * 1024` in a
  `before_request` of the blueprint for its POST routes); every other route keeps 1 MB.
- Activity entries carry the reference, kind, action, status from/to and actor only, never summary, text or file names.
- Tests: browser files start `pytestmark = pytest.mark.browser`, sign in with `browser_sign_in`, use `RECORDER` and end
  with `window.__csp == []` and `window.__errors == []`; POSTs use `conftest.post` (CSRF). Run each task's tests plus
  `tests/test_templates.py` with `M=/mnt/c/Users/AlexKrovina/Documents/GitHub/tc-trackers;
  $M/.venv/bin/python -m dotenv -f $M/.env run -- $M/.venv/bin/pytest <tests> -n 6 -q` (sandbox disabled). 7
  `mail/access/*.html` CSP failures exist on main.

## Review Focus

- A person without Manage feedback who guesses another request's id or a file id gets 404 on the request, its panel
  and its files (Task 4 and 5 tests).
- A file renamed to `.png` that is really HTML or SVG is refused at upload (Task 1 test).
- SMTP not configured, or the feedback address empty, never loses or blocks a request; the request shows "Email not
  sent: …" (Task 2 test).
- The Feedback link switched off hides the link and refuses the form (404), while My feedback and Admin › Feedback keep
  working (Task 3 test).
- A body over 26 MB, or a sixth file, or a 6 MB file, is refused with the reason and nothing is saved (Task 2 test).

### Task 1: Data, rules and settings

**Files:** Modify `tracker/models.py`, `tracker/auth/permissions.py`; create `migrations/versions/0015_feedback.py`
(revision `"0015"`, down `"0014"`), `tracker/feedback/__init__.py` (blueprint `bp = Blueprint("feedback", __name__)`,
registered in `tracker/app.py`), `tracker/feedback/service.py`, `tracker/feedback/settings.py`; tests
`tests/test_feedback_service.py`, `tests/test_migration_0015.py`.

**Interfaces (produced):**
- `FeedbackRequest` (`feedback_requests`): `id` identity; `kind` text check in ('idea','problem'); `summary` text;
  `details` text default ''; `status` text check in the seven keys below; `sender_id` FK users SET NULL; `page_title`,
  `page_url`, `browser` text default ''; `created_at`, `last_activity_at` timestamptz default now; `sender_seen_at`
  timestamptz null; `email_note` text default ''. Indexes `(status, last_activity_at)`, `(sender_id)`.
- `FeedbackMessage` (`feedback_messages`): `id`; `request_id` FK CASCADE; `author_id` FK users SET NULL; `role` in
  ('sender','reviewer','system'); `kind` in ('message','update','question','status','email'); `body` text default '';
  `status_from`, `status_to` text null; `created_at`. Index `(request_id, id)`.
- `FeedbackFile` (`feedback_files`): `id`; `request_id` FK CASCADE; `message_id` FK feedback_messages CASCADE;
  `filename` text; `content_type` text; `size` int; `data` bytea; `created_at`.
- `service.py`: `STATUSES = ("new", "under_review", "waiting", "planned", "done", "will_not_do", "withdrawn")`,
  `STATUS_LABELS` ("New", "Under review", "Waiting for an answer", "Planned", "Done", "Will not do", "Withdrawn"),
  `OPEN = STATUSES[:4]`, `CLOSED = STATUSES[4:]`; `reference(request_id: int) -> str` ("FB-0042");
  `@dataclass ValidFile(filename, content_type, data)`; `check_files(files: list[FileStorage]) -> tuple[list[ValidFile],
  list[str]]`; `create_request(session, sender: User, kind, summary, details, page_title, page_url, browser, files) ->
  FeedbackRequest`; `reviewer_reply(session, request, author: User, kind: Literal["update","question"], body, files) ->
  FeedbackMessage`; `set_status(session, request, author: User, status: str) -> None`; `sender_message(session,
  request, body, files) -> FeedbackMessage`; `withdraw(session, request) -> None`; `mark_seen(session, request) ->
  None`; `has_new_reply(request) -> bool`; `unread_count(session, user_id: int) -> int`; `new_count(session) -> int`;
  `replies(request) -> int`. None commits; each records Activity (`feedback_sent`, `feedback_replied`,
  `feedback_status`, `feedback_answered`, `feedback_withdrawn`; entity `feedback`, detail per Global Constraints) and
  bumps `last_activity_at`.
- `settings.py`: `ADDRESS_KEY = "feedback_email"`, `LINK_KEY = "feedback_link"`; `addresses(session) -> list[str]`;
  `link_on(session) -> bool` (default True); `parse_addresses(text: str) -> tuple[list[str], str | None]` (error
  "Enter valid email addresses, separated by commas." or "Enter at most 10 addresses.").
- Permission `manage_feedback`: ("Manage feedback", "Read, reply to and change the status of feedback in Admin ›
  Feedback."), in the Application group.

- [ ] Tests first: `reference(42) == "FB-0042"`, `reference(12345) == "FB-12345"`; `check_files` accepts a real PNG
  and a PDF, refuses a sixth file ("Attach at most 5 files."), a 6 MB file ("[name] is over 5 MB."), an `.exe`, and an
  HTML file named `shot.png` ("[name] is not a picture, PDF, Word, Excel or text file."); `create_request` stores the
  request (status new), one sender message and its files, and one Activity row with no summary in `detail`;
  `reviewer_reply(kind="question")` sets status waiting, `"update"` leaves it; a reviewer may reply to and re-status a

  `mark_seen`; `unread_count`, `new_count`, `replies` (updates and questions only); `parse_addresses("a@x.com, b@y.org")`
  and its two errors; `link_on` defaults to True; the migration up and down; `manage_feedback` listed in Application.
